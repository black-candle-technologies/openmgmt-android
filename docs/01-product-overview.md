# Product overview and feature matrix

> Source snapshot: `e53308af3921f454be1c661691b1fe546cb8f679` · reviewed 2026-10-11 UTC. See [scope and evidence](README.md#scope-and-evidence).

## Purpose and maturity

OpenMGMT Android stores a personal working set of organizations, projects, and tasks on an Android device. It provides task capture, status changes, due dates, organizational structure, summary views, and manual synchronization with the OpenMGMT service. The root README calls the application a scaffold under active development; the inspected source nevertheless contains nine routed screens, working local persistence paths, an OAuth client, an event log, and a sync engine. The accurate product description is an implemented Android client with deliberately limited scope and an early maturity label, rather than an empty scaffold. [README status](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/README.md#L1-L25) [Screen dispatch](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/MainActivity.kt#L92-L109)

The package and application ID are `com.openmgmt.android`. The build declares minimum API 26, compile API 34, target API 34, version name `0.3.3`, and version code `7`. These are the source's declared build values; they do not establish the version currently installed on a user's device or distributed through any store. [Build identity](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/build.gradle.kts#L9-L19)

## Product model

The logical hierarchy is organization → project → task. Saving a project with a null parent creates or reuses a live organization named `Personal`; saving a task with a null parent creates or reuses a live `Inbox` project under that organization. Names are matched case-insensitively for these defaults. The relationships are application-level conventions rather than database foreign keys. Existing non-null parent IDs are not validated by the save path. [Defaults and identity matching](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L21-L39) [Default creation](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L143-L161) [Entities](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L47-L87)

A task has one stored status. Eight statuses are selectable: `inbox`, `backlog`, `scheduled`, `ready`, `in_progress`, `blocked`, `waiting`, and `done`. `canceled` is the hidden archive state used by Delete. Projects support `active`, `paused`, `completed`, and a hidden `archived` state. Organizations are archived through a timestamp. These concepts are distinct from synchronization account identity: creating an organization does not create a tenant, invite members, or grant permissions. [Status constants](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L18-L45) [Archive operations](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L92-L141)

## Implemented capabilities

| Area | Implemented behavior | Practical boundary |
|---|---|---|
| Task capture | Title, notes, selectable status, due date, and project | No priority control, attachment upload, checklist, or recurrence editor |
| Task completion | Checkbox marks done; checkbox on done returns to ready | Reopening does not remember a previous status |
| Undo | Short snackbar for completion and deletion | One currently visible opportunity; no persistent recycle-bin screen |
| Tasks screen | All/status filters and sorted list | No text search, bulk selection, or project filter |
| Dashboard | Counts, attention list, active projects, quick creation | Summary lists are capped; metric navigation does not pass a target filter |
| Daily Operations | Overdue plus today focus; five upcoming tasks | Uses due dates and local device time |
| Schedule | Overdue, Today, Next 7 days, Later, Unscheduled | No hourly calendar, reminders, or scheduling service |
| Board | Four selected-column views | One column at a time; no drag-and-drop movement |
| Projects | Create, rename, change status, choose organization, archive | Tapping a project opens editing, not a task detail route |
| Organizations | Create, rename, archive, project/open-task counts | No organization permissions or membership model |
| Account | System-browser OAuth with PKCE and dynamic registration | UI displays signed-in state, not user name/email or account selector |
| Sync | Register device, pull events, replay, push queued mutations | User initiates; no background worker or periodic timer |

| Appearance | System-dependent light/dark theme and responsive gutters | No user theme preference, localization catalog, or measured accessibility certification |

## Local-first operation

The app does not require sign-in to create or edit records. Screens observe Room through `MainRepository` and `MainViewModel`, and local mutations append sync events in the same transaction as entity changes. While signed out, those pending rows can accumulate. A first standalone task can generate three pending events: creation of `Personal`, creation of `Inbox`, and creation of the task. “Changes to send” counts events, not distinct tasks. [Repository flows and task save](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L48-L87) [Default creation](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L146-L171) [Pending count query](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L169-L176)

Deleting a record in the UI is a retained-state operation. It changes an entity's archive representation and creates an event for other devices. Archiving a project hides its tasks in `MainViewModel`, without canceling each task. Archiving an organization hides the organization, but the project DAO does not join against live organizations, so its projects and tasks can remain visible. This difference matters when assessing whether data is truly missing. [Visibility queries](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L119-L162) [Task parent filter](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/ui/MainViewModel.kt#L22-L26)

## Synchronization product contract

The configured server is `https://openmgmt.blackcandletech.com`; the configured OAuth issuer is `https://auth.blackcandletech.com`. Both are compile-time defaults in ordinary constructor parameters, not editable fields. Registration is the only sync request that carries the OAuth access token in a Bearer header. Pull and push carry the device credential inside the JSON `auth` object. No account secret is needed to work locally. [Sync defaults and registration](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncManager.kt#L32-L37) [Registration and auth context](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncManager.kt#L73-L96) [OAuth defaults](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/OAuthConfig.kt#L12-L17)

The account session and sync device registration are separate states. The UI permits sync when either an OAuth access-token preference exists or a device token exists. A registered installation can continue to sync even if OAuth credentials are no longer present. Successful sign-in does not immediately synchronize: the success message tells the user that the next sync will register the device. [State and sign-in](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/ui/SyncViewModel.kt#L20-L68)

Conflicts are resolved through event replay and local pending protection, not collaborative field merging. Android pulls before pushing; remote events for an entity with pending local events are skipped and marked applied, and the full local entity is subsequently pushed. This preserves the local edit but can overwrite concurrent remote changes to other fields. The preservation of desktop-only fields applies to the last remote JSON Android actually accepted, not to remote events it skipped. [Remote replay](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L221-L289) [Outgoing merge basis](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncPayloads.kt#L24-L32)

## Explicitly absent surfaces

The complete source tree has one application module. It has no web frontend, backend server, CLI, Android service, broadcast receiver, WorkManager integration, notification permission, alarm setup, content provider, account-sharing screen, push messaging integration, or plugin loader. There is no in-app export/import or administrative database browser. The only declared platform permission is `INTERNET`. These are negative findings from the full tree and manifest, not promises about future releases. [Manifest](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/AndroidManifest.xml#L1-L36) [Module configuration](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/settings.gradle.kts#L15-L16)

Do not import desktop marketing claims into Android user documentation without checking an Android control and a corresponding repository mutation. Fields such as tags, scheduling metadata, and estimated minutes may be preserved through sync even though they have no Android controls. Likewise, the Android board resembles the desktop's presentation concept but does not implement every desktop board feature. See [entity interoperability](16-entity-json-interoperability.md) for the exact field contract.

## Suggested usage patterns

For a single person's phone and desktop, a useful routine is to capture and organize work locally, then explicitly sync before switching devices and again before making edits on the next device. This reduces overlapping edits but cannot eliminate races between clients. For a shared phone or account handoff, the retained database and automatic full snapshot require a separate data-management process; signing out alone is insufficient. These are operational recommendations derived from the sync and sign-out behavior, not built-in workflows.
