# Security boundaries, privacy, and hardening priorities

> Source snapshot: `e53308af3921f454be1c661691b1fe546cb8f679` · reviewed 2026-10-11 UTC. See [scope and evidence](README.md#scope-and-evidence).

## What this assessment establishes

This is an implementation-based security chapter within a complete documentation review. Every tracked file was read, but no instrumented exploit, mobile penetration test, dependency-advisory scan, live account boundary test, or server configuration audit was performed for this Android repository. Findings below distinguish observed behavior from plausible consequences and recommended changes. No finding should be rephrased as an independently confirmed remote compromise.

The application is one Android process with local Room storage, encrypted preference stores, a browser OAuth boundary, and outbound HTTPS defaults for auth and sync. The only declared permission is INTERNET. The only declared activity is exported MainActivity, serving both launch and OAuth callback paths. [Manifest surface](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/AndroidManifest.xml#L1-L36) [Application construction](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/OpenMgmtApp.kt#L21-L30)

## Assets and trust boundaries

| Asset / boundary | Implementation | Security implication |
|---|---|---|
| Task/project/organization records | Normal Room database and full entity JSON | Local app data and backups can contain private work, including hidden desktop fields |
| Outbox and accepted history | Payloads retained in sync_events | Past values can persist beyond current visible records |
| OAuth access/refresh credentials | Encrypted preferences | Protected separately from Room; usable in app memory/network when needed |
| Device token | Separate encrypted preference store | Authenticates push/pull independently of OAuth presence |
| Browser callback | Exported custom-scheme activity entry | Incoming intent is untrusted until flow state/code checks pass |
| Auth service | DCR, authorization, token endpoint | Must enforce client/redirect/PKCE/refresh policy |
| Sync service | Receives account token at registration, device token and entities later | Server must authenticate and authorize returned/accepted events |
| GitHub build | Gradle executes repository code | Workflow token and signing material must be appropriately scoped |

## Implemented protections

The native flow uses a system browser, no embedded client secret, S256 PKCE generated with SecureRandom, and a random state value. Token exchange and refresh run off the main thread. The refresh path uses a mutex to reduce overlapping use of rotating refresh tokens. Pending verifier/state are persisted for process-death continuity. [PKCE](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/Pkce.kt#L8-L31) [Browser authorization](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L79-L115) [Refresh serialization](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L171-L185)

Local mutation/event pairs are atomic, pulled page bookkeeping commits transactionally, remote envelope/entity ID equality is checked, and acknowledgments only clear event IDs present in the batch actually sent. These are meaningful data-integrity defenses, although they do not constitute cryptographic authentication of event content. [Local transaction](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L62-L87) [Replay checks](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L231-L289) [Acceptance filtering](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncManager.kt#L146-L152)

Both GitHub workflows request contents:read, disable persisted checkout credentials, pin action references to full commits, and set 15-minute job limits. Dependabot covers GitHub Actions weekly. No repository signing secret is configured in the inspected workflows. [CI permissions/pins](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/.github/workflows/ci.yml#L13-L41) [Dependabot](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/.github/dependabot.yml#L1-L11)

## Account boundary: retained data can transfer to the next account

**Observed:** signing out retains every business row, resets device identity, clears the checkpoint, and marks a full snapshot pending. After another account signs in, a later sync materializes all retained organizations/projects/tasks, including archives, before pull and attempts to push them under the newly registered account's device credentials. Transfer to the remote account depends on successful requests and server acceptance. The database does not partition business records by account. The UI exposes only signed-in presence, not the account subject/name. [Disconnect contract](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncManager.kt#L50-L58) [Snapshot scope](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L184-L219) [Entity columns](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L47-L87)

**Consequence:** the app cannot safely be documented as supporting independent accounts on one installation. Account switching can disclose a prior user's local dataset to a different account or overwrite remote state with retained local copies. This transfer is explicitly described in code comments, so it is a product-boundary decision as well as a security concern.

A separate identity mismatch is possible when OAuth sign-in occurs while a device registration is retained. Sign-in refreshes only account-token state; `run` registers initially only when `isRegistered` is false, and otherwise uses stored device account/user IDs and token. A new OAuth sign-in therefore does not prove that an existing device registration was rebound to that account. The UI exposes neither subject for comparison. The resulting server authorization outcome depends on the device-token and re-registration policy, which is outside this Android source. [Sign-in updates](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/ui/SyncViewModel.kt#L52-L68) [Stored context and registration condition](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncManager.kt#L91-L110)

**Recommendation:** choose an explicit design before multi-account distribution: per-account databases and outboxes; an account-associated workspace with verified subject IDs; or a deliberate user-reviewed migration operation. Sign-out should have clear retention/disconnect semantics, and the next account must not inherit a prior dataset by an implicit snapshot. Include pending edits, archived rows, dedupe IDs, and crash recovery in tests.

## Backup and local storage

**Observed:** the manifest enables backup and provides no explicit backup/data-extraction rules, while token stores use encrypted preferences. Room is opened with the normal builder and no custom encrypted database provider. Neither task contents nor event payloads receive application-level encryption here. [Manifest](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/AndroidManifest.xml#L6-L12) [Room builder](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L283-L294)

**Consequence:** app credential encryption must not be marketed as whole-database encryption or end-to-end synchronization encryption. Restoring encrypted preferences onto a device without the expected key can fail; [the recovery chapter](12-migrations-backup-and-recovery.md) includes the primary Android reference and required distinction between records and device-bound credentials.

**Recommendation:** implement explicit backup rules, verify restore with and without the original key, recover unusable credentials without discarding valid records, and define business-data retention/encryption needs separately. Secure preferences still decrypt into application memory during use; they do not defend against arbitrary execution inside the app process or a compromised device.

## OAuth callback hardening

**Observed:** MainActivity checks only scheme/path. AuthManager removes pending state/verifier before validating the callback state or error. A matching invalid callback can invalidate a legitimate pending attempt. The timeout does not erase pending values, and sign-out does not serialize against every possible token-exchange completion. [Dispatch predicate](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/MainActivity.kt#L122-L138) [Consume before validate](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L125-L143) [Timeout cleanup](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L111-L115) [Sign-out](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L187-L198)

**Consequence:** externally supplied links can interrupt a pending flow. The source does not establish token theft because a valid code/state/verifier exchange is still required. The in-flight state handling has a narrower protection boundary than its “captured redirect must not be replayable” comment implies: preference removal alone is not a complete atomic flow-consumption strategy.

**Recommendation:** compare the callback against the configured URI's expected scheme, absent authority, and exact path; validate state before consuming the matching transaction; store an attempt ID and expiry; serialize consumption; and reject token results from stale/canceled generations. Test valid warm/cold callbacks, unrelated links, invalid state, two callbacks, browser dismissal, timeout, and sign-out during a delayed exchange. Do not log authorization codes or verifier values while diagnosing these cases.

## Refresh reliability and token revocation

**Observed:** every non-2xx refresh response clears access/refresh/expiry, even a transient server error. A successful response lacking refresh_token removes the previous token. There is no remote revoke/logout request in sign-out. Device credentials remain distinct from OAuth, and a registered-but-signed-out UI state can still synchronize without a visible Sign out button. [Refresh behavior](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L239-L252) [Failure clearing](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/AuthManager.kt#L304-L316) [UI states](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/ui/screens/SyncScreen.kt#L94-L123)

**Recommendation:** classify temporary HTTP failures separately from invalid_grant, preserve a still-valid refresh credential when appropriate to the issuer contract, expose device disconnect independently from account sign-out, and provide a tested server revocation path where required. Do not assume deleting a local preference invalidates a token already issued by either service.

## Server trust and transport

All configured defaults use HTTPS. OkHttp is constructed without custom trust-all code or certificate pinning. Sync device registration sends the OAuth access token as a bearer credential to `/omgp/v1/devices/register`; the device token appears in JSON bodies for pull/push. There is no message encryption layer, signature verification, or encrypted-envelope protocol in this app. Sync server operators can receive entity contents and credential-bearing requests. [Default endpoints](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/auth/OAuthConfig.kt#L12-L17) [Sync server and auth](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/SyncManager.kt#L32-L37) [Registration request](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/OmgpClient.kt#L12-L25) [HTTP construction](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/OmgpClient.kt#L35-L60)

The client does not authorize remote actor_user_id, target_user_id, workspace_id, or account routing locally. It trusts the sync service to return the correct dataset. A malicious or faulty service can supply oversized pages, unsupported records, arbitrary entity contents within parser limits, or misleading acceptance/rejection fields. Category sorting and ID matching do not replace service-side access control. [Envelope fields](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/sync/OmgpModels.kt#L64-L78) [Remote handler](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L259-L289)

**Recommendation:** validate server account isolation and device-token ownership, prevent credential-bearing request-body logging, bound response sizes and pagination progress, and document endpoint changes as a data/credential routing change. Constructor configurability is not an end-user permission to send production account tokens to any arbitrary test server.

## Event handling, retention, and visibility

Malformed and unsupported remote events are logged, marked processed, and not retried automatically. This can hide interoperability or integrity problems behind apparent progress. RemoteJson preservation can lose concurrent changes when local pending events shield a record. Archived records, accepted event history, and processed IDs have no pruning mechanism. [Replay behavior](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L244-L255) [Outbox methods](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Database.kt#L164-L201)

**Recommendation:** maintain an observable, redacted failed-event quarantine; distinguish skipped from successfully applied counts; plan retry semantics across client upgrades; and define retention without breaking idempotency or sync recovery. User-facing Delete should state retained/archive behavior, particularly for privacy-sensitive data.

## Logging and release controls

The code logs callback exceptions and skipped-event exceptions under OpenMGMT. The sync UI displays exception messages and counts rather than raw bodies. There is no app telemetry SDK or generic request logger in the tree, but exception strings and user-controlled event IDs can still carry sensitive context. Redact codes/tokens, private notes, and complete payloads before sharing logs. [Callback logging](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/MainActivity.kt#L129-L134) [Event logging](https://github.com/black-candle-technologies/openmgmt-android/blob/e53308af3921f454be1c661691b1fe546cb8f679/app/src/main/java/com/openmgmt/android/data/Repository.kt#L247-L250)

A debug CI APK is not a release-signing policy. Protect production keys, verify signer identity across updates, test minified builds, and keep developer debugging access out of production acceptance criteria. [Release engineering](21-ci-release-and-dependencies.md) details what CI actually does.

## Suggested engineering order

Prioritize account-boundary behavior and backup recovery first because they affect user data transfer and recoverability. Next harden callback/session lifecycle and expose accurate rejected/skipped diagnostics. Then add protocol/migration tests, bounded synchronization, reproducible wrapper bootstrap, and dependency-maintenance coverage. These priorities are recommendations based on inspected behavior; none is represented as completed remediation.
